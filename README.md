# nijatva-core — shared libraries for the Nijatva suite

One fix here reaches every app. No copy-paste.

## Modules

| Module | What it is |
| --- | --- |
| `:signature` | The two screens every Nijatva app carries — **Appearance** (theme, accent, dynamic colour) and **Developer** (who made it, the suite, the figures). Plain framework Java: no AndroidX, no Kotlin, no resources, no dependencies. |

## `:signature`

```
signature/
├── build.gradle.kts                 com.android.library · namespace com.nijatva.signature
└── src/main/
    ├── AndroidManifest.xml          declares both activities + the family <queries>
    └── java/com/nijatva/signature/  Signature, SignatureTheme, SignatureViews, SignatureIcon,
                                     SignatureAppearanceActivity, SignatureDeveloperActivity,
                                     SignatureScreenActivity, SignatureTrust, SignatureDevInfo
```

Because the activities are declared in the **library** manifest, an app does not edit its own
manifest at all — manifest merging adds both screens and the package-visibility `<queries>`.

### Add it to an app

**Option A — local Maven (recommended while everything lives on one machine)**

```sh
# once, in this repository
./gradlew :signature:publishToMavenLocal
```

```kotlin
// in the app's settings.gradle.kts
dependencyResolutionManagement { repositories { google(); mavenCentral(); mavenLocal() } }

// in the app's build.gradle.kts
dependencies { implementation("com.nijatva:signature:1.0.0") }
```

**Option B — drop the AAR in**

Copy `signature-release.aar` to the app's `app/libs/`, then:

```kotlin
dependencies { implementation(files("libs/signature-release.aar")) }
```

**Option C — composite build** (both repos side by side, no publishing)

```kotlin
// app's settings.gradle.kts
includeBuild("../nijatva-core")
// app's build.gradle.kts
dependencies { implementation("com.nijatva:signature:1.0.0") }
```

### Open the screens

```java
startActivity(Signature.appearance(this));   // Appearance
startActivity(Signature.developer(this));    // Developer card
```

Optional — let the app's own chrome follow the accent the user picked:

```java
int accent = SignatureTheme.accent(this);
boolean dark = SignatureTheme.isDark(this);
```

### What the card reports

Read from the device at open time, not claimed: version name and code, the **APK signing
certificate SHA-256**, whether the app declares `INTERNET` at all, and which sibling Nijatva
apps are installed. The suite figures come from `SignatureDevInfo`, generated by
`tools/generate_devinfo.py` from `tools/apps.json`.

## Versioning

`version = "1.0.0"` in `signature/build.gradle.kts`. Bump it when the kit changes, publish,
and every app picks the change up on its next build. Keep the same signing key across the
suite so the certificate line on the card reads identically everywhere.
